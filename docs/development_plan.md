# 開発計画（SVG PowerPoint-like Editor）

## スプリント0（前提整理）
1. プロダクト目的と対象ユーザーの合意
2. 技術スタック固定（HTML/CSS/Vanilla JS + SVG）
3. データ構造（slides, elements）を確定
4. 開発開始チェック: 主要イベント（追加/選択/移動/保存）を確認

## スプリント1（MVP実装）
- スライド管理UI（リスト、追加、複製、削除）
- SVGキャンバスに要素描画
- テキスト・四角形・円・画像の追加
- 選択/ドラッグ移動/リサイズの実装
- 最低限のデータ保存（localStorage）

## スプリント2（編集体験改善）
- プロパティ編集（色・文字サイズ・テキスト）
- 要素の重なり順変更
- バリデーション/エラー表示改善
- キーボード操作（Delete）
- モバイル表示でのUI崩れ対策

## スプリント3（I/O強化）
- JSONインポート/エクスポートの堅牢化
- SVGエクスポートの形式検証
- ファイルの破損耐性（安全な読込）
- SVGインポート機能（rect/circle/ellipse/text/image）を実装
- スライドごとのundo/redo検討（実装有無を別途判断）

## スプリント4（将来拡張の事前準備）
- 選択範囲枠・多重選択
- グリッド/スナップ/吸着
- テキストの改行/文字装飾
- 図形テンプレート
- プレゼンテーション再生モード

## リスク
- SVG要素が増えた場合の描画遅延
- localStorage容量の上限（大量スライド時）
- 外部画像URLのCORSや404影響

## 開発の優先順位（PoC向け）
1. 安定して動く編集ループ
2. データの保存と復元
3. 操作性の向上（リサイズ/移動）
4. エクスポート
5. 拡張機能
